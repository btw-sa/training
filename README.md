# BTW Training

Staff training for By The Way: product cards (one PDF per product) viewed inside the site, a quiz
after each section's cards, a final assessment, practical skill sign-offs, certificates with a public
check page, and dashboards limited to each manager's branches. Arabic and English, phone first,
light theme with an optional dark theme.

**Status (14 Oct 2026): ready to go live.** The site starts empty. The owner creates the one
Administrator account on the first-run screen, then adds branches, people, courses and cards.
Step-by-step instructions: [docs/go-live.md](docs/go-live.md).

## How it fits together

```
 Staff phone / browser                         Supabase (your project)
 ┌───────────────────────────┐   HTTPS   ┌────────────────────────────────────────────┐
 │ GitHub Pages: index.html  │ ────────▶ │ Edge Function btw-api                       │
 │  + config.js (URL + public│           │  · same permission engine (core.js)         │
 │    key, nothing secret)   │           │  · signs sessions, hashes passwords (PBKDF2)│
 │ keeps only the signed-in  │ ◀──────── │  · returns each person only their own copy  │
 │ person's own copy         │           ├────────────────────────────────────────────┤
 │ card viewer (pdf.js)  ◀───┼─ signed ──│ Storage bucket "cards" (private, PDF only)  │
 └───────────────────────────┘   links   │ Postgres: app_state, history, audit_log     │
                                         └────────────────────────────────────────────┘
```

- **One set of rules.** `web/src/core.js` holds every permission check (roles, Admin-granted Area
  Manager access, branch scope, rank). The server runs it on the full data for every change; the
  browser runs the same code on the person's own copy only to draw screens.
- **Nothing private in the browser or the repository.** The browser gets its own records and names
  of people in visible records; never password hashes, never other people's notifications, never
  correct answers unless that person edits that exam. Secrets (service key, `SETUP_CODE`,
  `SESSION_SECRET`) stay in Supabase.
- **Product cards.** Managers upload PDFs in bulk ("01 - Espresso.pdf" → card 1, "Espresso"). Staff
  go through them in order in the viewer (swipe, keyboard, zoom); each card must stay on screen a set
  number of seconds (Settings → Training). The section quiz opens after the last card.
- **Trial copy.** Without `config.js` settings (for example in the Claude preview), the same page
  runs entirely in the browser and keeps data on that device only, with a banner saying so.

## What is in this repository

| Path | What it is |
| --- | --- |
| `web/src/` | The app. `core.js` permission engine and data rules; `ui-*.js` screens (`ui-cards.js` is the card viewer and uploads); `i18n.js` every English and Arabic string; `styles.css` BTW identity. |
| `server/` | The live server: `handler.js` (operations, sessions, setup code, uploads), `deno-entry.js` (Supabase Edge Function wrapper), `dev-adapters.js` (in-memory stand-ins for tests). |
| `supabase/setup.sql` | Run once in the Supabase SQL editor: tables, locked-down access, save function, private `cards` bucket. |
| `supabase/functions/btw-api/index.ts` | The server as one file (generated by `npm run build`). Paste it into the Supabase dashboard, or deploy with the CLI. |
| `config.js` | The one file you edit after setting up Supabase: project URL and publishable key. |
| `scripts/` | `build-prototype.js` (builds `site/` for GitHub Pages and `web/dist/index.html`, the trial copy), `build-function.js`, `dev-server.js` (local stand-in for the live site). |
| `.github/workflows/` | `ci.yml` tests; `pages.yml` publishes the site on every push to `main`; `deploy-function.yml` optional server update. |
| `web/test/`, `supabase/tests/` | Engine (36), server (11), database (4), Deno function and browser tests. `fixtures.js` holds fictional test data used only by tests. |
| `docs/` | `go-live.md` (setup and day-to-day running); `archive/` (an earlier database design, not used). |

## Run it locally

```bash
npm ci
npm test                 # engine, server and database tests
npm run build            # site/ and web/dist/index.html
npm run dev              # live-site stand-in on http://127.0.0.1:8788 (setup code: dev-setup-code)
python3 web/test/smoke_test.py . /tmp/shots          # browser tests (pip install playwright)
python3 web/test/live_e2e.py /tmp/shots/_cards /tmp/shots-live
```

## Rules the code keeps

- Every change is checked on the server with the signed-in person's identity; the browser cannot
  pick who it acts as. Hiding a button is never the protection.
- Passwords are stored as PBKDF2-SHA256 hashes (600,000 rounds) and never leave the server.
- Learners never receive correct answers before submitting; grading happens on the server.
- Records with history are deactivated, archived or revoked, never deleted; corrections need a
  reason; every change is written to `audit_log`.
- Card PDFs are private: the server hands out one-hour links only to people assigned the course or
  managing it.
- No staff data, credentials, card PDFs or exports go into this repository (`.gitignore` blocks them).
